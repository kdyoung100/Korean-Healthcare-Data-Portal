# 보건의료데이터 중개 포털 (프로토타입)

흩어져 있는 보건의료 데이터셋(공공데이터·임상데이터)을 한 곳에서 찾고, 데이터마다 범위·항목·신청 방법과
**이 데이터로 나온 논문·연구자**까지 확인한 뒤 실제 신청 창구로 연결해 주는 웹사이트입니다.

- 사이트: https://kdyoung100.github.io/Korean-Healthcare-Data-Portal/
- 등록 데이터셋 355건 · 제공기관 67곳 · 검수된 논문 57편(결핵 시범) · 연구자 207명
- 서버 없이 GitHub Pages로 서비스하며, 엑셀을 고쳐 푸시하면 자동으로 다시 빌드·배포됩니다.

---

## 기능

### 1. 대화형 AI 검색
자연어로 물어보면 질문의 의도를 알아서 구분해 서로 다른 화면으로 답합니다.

| 이렇게 물으면 | 이렇게 보여줍니다 |
|---|---|
| **데이터** — "결핵 데이터 찾아줘" | 데이터셋마다 설명·활용 방안·관련 연구·주요 연구자를 **항목 카드**로 정리한 AI 답변, 그 아래 데이터셋 카드(최신 논문 3편과 연구자 포함) |
| **논문** — "결핵 논문", "이 데이터로 연구한 논문과 연구자 알려줘" | 요약 한 줄 + 최신 논문 카드(한국어 설명·저자·기관·사용 데이터), 데이터별 전체 논문 목록(10편씩 페이지)과 연구자 목록 |
| **연구자** — "결핵을 연구한 연구자 찾아줘", 영문 이름(예: "Young Ae Kang") | 연구자 카드(소속, 논문 수, 제1저자·교신저자 편수, 사용한 데이터, 최근 논문) — 논문 수 순으로 12명씩 페이지 |

- 답변 속 **데이터셋명·연구자 이름·논문 제목은 누르면 이동**합니다. 목록에 실제로 있는 이름에만 링크가 붙어,
  AI가 지어낸 이름에는 링크가 생기지 않습니다.
- "이 데이터로 연구한 논문은?"처럼 **이어서 물으면** 직전에 찾은 데이터를 이어받습니다.
- **논문 질문은 AI를 부르지 않고** 검수된 논문 DB만으로 바로 답합니다(빠르고, AI 오류의 영향을 받지 않음).
- AI 검색 화면은 필터 없이 결과를 넓게 보여주며, 관련 **웹 검색 결과**도 함께 나옵니다.
- 화면 오른쪽 아래 **챗봇**도 같은 방식으로 답합니다.

### 2. 논문·연구자 연계 (PubMed, 결핵 시범)
- 데이터셋마다 **"이 데이터로 연구된 논문"** 을 붙입니다. PubMed 공식 API(NCBI E-utilities)로 후보 논문을 모은 뒤,
  초록(필요하면 원문)을 읽고 **그 데이터를 실제 분석에 쓴 논문만** 남깁니다(결핵 신고자료: 후보 102편 → 확인 57편).
- 논문마다 **한국어 1~2줄 설명**이 붙고, 제목을 누르면 PubMed 원문으로 갑니다.
- 저자 정보(이름·소속)로 **연구자 색인**을 만들었습니다. 연구자를 누르면 그 연구자의 논문 전체, 연구에 쓴 데이터,
  PubMed 저자 검색 링크를 보여주는 **연구자 카드**가 열립니다. 소속은 국내 주요 기관을 한글명으로 정리해 보여줍니다.
- 사이트를 여는 사람은 PubMed를 부르지 않습니다. 논문은 미리 모아 검수한 `논문DB.xlsx`에서 빌드할 때 들어갑니다.

### 3. 데이터셋 검색
- 이름·기관·키워드·설명·테이블명으로 검색(여러 단어는 모두 포함된 것만)
- 필터: 구분(임상/공공), 주제, 공급 기관, 수집 기간
- 정렬: 관련도 / 최신 업데이트 / 조회수 / 이름순 · 보기: 카드형 ↔ 표 · 10건씩 페이지

### 4. 데이터셋 상세 페이지
- 데이터셋 정보표(기관, 수집기간, 항목, 테이블, 규모, 업데이트 주기, 신청절차 등)
- **신청 창구 바로가기** — 데이터셋 ID로 K-CURE, 보건의료 빅데이터 통합 플랫폼, 의료데이터 중심병원, 기관 직접 신청을 자동 연결
- 자료집 기반 **상세 안내**(개요, 데이터 범위·최신성, 분석 환경, 데이터 획득·결합 등)
- **이 데이터로 연구된 논문**(한국어 설명 포함)과 **이 데이터로 연구한 연구자**
- 같은 기관의 관련 데이터셋

### 5. 메인 화면
통합 검색(대화형 AI 검색 기본), 리소스 탐색 카드, 주제별(임상/공공) 데이터 탐색, 주요 공급기관·최신 데이터셋,
이용 절차·공지 페이지, 이용자 유형별 안내.

> 메인의 "인기 데이터" 조회수와 누적 신청 건수는 실제 통계가 생기기 전까지의 **표시용 값**입니다.

### 6. 수정 요청 메모
화면 어디서든 **오른쪽 클릭(모바일은 길게 누르기)** 으로 "이 부분이 틀렸어요" 같은 메모를 남길 수 있고,
남긴 메모는 해당 위치에 노란 핀으로 표시됩니다.

## 저장소 구성

```
index.html                          사이트 전체 (HTML/CSS/JS 한 파일)
chatbot-icon.png                    챗봇 버튼 이미지
build.py                            엑셀 → data.json 생성 (배포 때 GitHub Actions가 실행)
paper_db.py                         논문DB 관리 도구 + build.py 가 논문을 읽을 때 사용
requirements.txt                    파이썬 의존성 (openpyxl)
중개포털_데이터_리스트_*.xlsx       원본 ① 검색 목록 (데이터셋)
자료입력양식.xlsx                   원본 ② 상세 안내 본문 (자료집)
자료집ID.json                       발급한 자료집ID 기록 — 지우지 말 것
논문DB.xlsx                         원본 ③ 데이터셋별 논문 (검수 결과·저자·한국어 설명)
.github/workflows/deploy.yml        빌드 & GitHub Pages 배포
```

`data.json`은 빌드 결과물이라 저장소에 올리지 않습니다. 배포할 때마다 새로 만들어집니다.

### 데이터 흐름

```
데이터 리스트.xlsx ─┐
자료입력양식.xlsx ──┼─ build.py ─→ data.json ─→ index.html (검색·상세·AI 검색)
논문DB.xlsx ────────┘   (datasets · guides · papers · researchers)
```

- 데이터 리스트와 자료입력양식은 **자료집ID**(예: `G26`) 열로 연결됩니다. 데이터 이름이 바뀌어도 연결이 끊기지 않습니다.
- 논문DB는 **데이터셋ID**로 연결되고, 사이트에는 검수상태가 **확인**인 논문만 나옵니다.
- AI 답변과 웹 검색 결과는 별도 서버(Cloudflare Worker)를 거칩니다. API 키는 그 서버에만 있고 이 저장소에는 없습니다.

## 데이터 고치기

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 검색 목록(기관명, 데이터명, 수집기간, 키워드, 신청절차 등) | `중개포털_데이터_리스트_*.xlsx` — **데이터셋** 시트 |
| 상세 안내 본문 | `자료입력양식.xlsx` |
| 논문 검수 결과·한국어 설명 | `논문DB.xlsx` — **논문** 시트의 `검수상태`(확인/제외/보류), `한줄요약` |

고친 뒤 `main`에 푸시하면 자동으로 빌드·배포됩니다. 데이터 리스트 파일이 여러 개면 파일명의 날짜가 가장 큰 것을 씁니다.

### 논문 새로 모으기 (로컬)

```bash
python paper_db.py fetch            # PubMed에서 모아 논문DB에 추가 (새 논문은 '미검수')
python paper_db.py pending 미검수.json   # 검수할 논문을 초록과 함께 뽑기
python paper_db.py review 결정.json      # 검수 결과(확인/제외/보류·근거·한국어 설명) 반영
python paper_db.py stats            # 상태별 건수
```

다시 모아도 사람이 적은 검수 칸(검수상태·근거·한줄요약·메모)은 덮어쓰지 않고, 행을 지우지도 않습니다.
검수가 끝난 `논문DB.xlsx`를 커밋·푸시하면 사이트에 반영됩니다.

## 로컬에서 미리 보기

```bash
pip install -r requirements.txt
python build.py              # data.json 생성
python -m http.server        # http://localhost:8000 접속
```

`index.html`을 더블클릭(`file://`)해서 열면 `data.json`을 읽지 못합니다. 반드시 위처럼 로컬 서버로 여세요.

## 배포

`main`에 푸시하면 GitHub Actions가 `build.py`를 돌려 `data.json`을 만들고 GitHub Pages에 올립니다
(Actions 탭의 **Run workflow**로 직접 실행할 수도 있습니다). 빌드 결과 요약(연결된 데이터셋·논문 수, 경고)은
Actions 실행 화면 맨 위에서 볼 수 있고, 빌드 중 새 자료집ID가 발급되면 `자료집ID.json`이 자동으로 커밋됩니다.
